The runner preserves six production processes, then runs six separate acceptance processes in a fresh GUID root after the production host and all owned workers exit. The variants share an upstream singleton. The acceptance native banner, `Ready · CI synthetic data` handshake and marked synthetic profile gate every provider-capable native operation. No API keys or Webhook values are entered. Its compiled worker uses actual Core with `SyntheticClient`, `SyntheticSummarizer` and `SyntheticDingTalk`; the latter replaces the HTTP transport with a local return value. A synthetic `sent` record is not real delivery.

The acceptance sequence configures verified synthetic scope and fake model cache through native controls, waits for a future due slot on the producer’s PC-local, every-calendar-day schedule to produce actual automatic history and a fictional summary, then stops the Running task and checks stable scheduler revision/database hashes beyond the real 15-second timer. Separate OS phases check unchanged protected key/binding restore without a page, idempotent Start/no duplicate worker, explicit Stop preventing restart despite retained Resume preference, changed-config and missing-key restore refusal without replacement authority, active Disable/worker retirement, re-enable Stopped and disabled restart/data retention. Disable clears running intent and the plugin's generated key/binding while preserving the separate Resume preference; re-enable must remain Stopped without a key, binding or worker. Reports contain actual host/worker PID and exit status, provenance, counts and hashes, without keys, MAC values, provider configuration or digest bodies. These checks are authored but require actual current shipping-App Windows evidence.

The schedule source uses naive PC-local `datetime.now()` and every calendar day; report-window conversion to Asia/Shanghai is separate and does not impose a workday filter. The probe records the actual local timezone/offset and due minute without changing the clock.

The pinned worker uses owned `TerminateJobObject(job, 1)` during final retirement after any idle shutdown attempt. Earlier production CI worker exit 1 is consistent with this producer contract and is reported as such; it is not claimed as graceful exit 0. The shipping host still must exit 0 after its actual Closed event and release its root lease.
