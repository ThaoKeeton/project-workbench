# Native source connectors and AI test authoring

## Purpose and limits

Continue the Windows-native plugin platform from `8e022a3d93588edead537936051ef101cc2806c5`. The testing plugin will expose its existing retained Figma reader in ordinary WinUI controls and add a real, bounded OpenAI Responses client for authoring test cases. Transport tests use in-memory handlers and synthetic credentials exclusively. No live API, credential provisioning, real Webhook, DingTalk message or user-PC operation is part of this phase. A following, separate phase will implement an owned synthetic Windows automation target and its restricted driver; it must not reuse the virtual target identity.

The workspace is the existing dedicated `feat/native-plugin-workbench` checkout. No business repository, main branch, release, draft PR, credential or remote storage setting is changed. In-process plugins remain trusted code, not a sandbox. No assembly hot-unload claim is added.

## AI client

Use only `POST https://api.openai.com/v1/responses`, model snapshot `gpt-5.4-mini-2026-03-17`, `reasoning.effort: none`, `store: false`, `stream: false`, `max_output_tokens: 8192` and a strict `text.format` JSON schema. There are no tools, file/image inputs, previous responses, conversations, redirects, cookies, default credentials, retries or URL traversal. API keys are obtained through one supplied async callback and put only in the per-request Authorization header. After lookup, refuse a captured input containing that exact credential in any decoded JSON string/property name, including escaped spellings, before HTTP; do not redact or truncate source text. Default clients are disposed after the actual work settles; injected handlers remain caller-owned.

`AiTestCaseGenerator(HttpMessageHandler? handler = null)` exposes `Task<AiGenerationCapture> GenerateAsync(IReadOnlyList<TestSourceSnapshot> sources, Func<CancellationToken, Task<string?>> getKey, CancellationToken cancellationToken = default)`. Construction performs no IO. Capture and validate caller inputs synchronously before credentials or HTTP. Accept 1–8 distinct source snapshots, each with valid lower-hex IDs/revisions and SDK-bounded text. Ignore OriginalBytes and VirtualScenario entirely. Include all selected items/criteria, at most 32 criteria in total. Reject the receipt provider `openai.responses.test-cases` as an input. The exact UTF-8 input JSON is at most 256 KiB. Preserve input order and literal text; do not truncate or infer criteria. Each criterion gets a zero-based index and its original snapshot/revision/locator/criterion trace.

The model returns exactly `{ cases: [{ criterionIndex, title, prerequisites, steps: [{ instruction, expected }] }] }`. All properties are required; every object has `additionalProperties: false`. Enforce 1–32 cases, 1–16 steps per case, at most 256 steps overall, title 1–200 UTF-16 units, prerequisites 0–4096, instruction/expected 1–4096, valid Unicode, nonblank required text and integer criterion indices in range. Every input criterion must be covered at least once. Refuse extra properties, duplicate JSON names and unpaired surrogates. The response must be a completed response for the requested snapshot, with a response ID of total 6–128 characters (`resp_` plus 1–123 ASCII alphanumeric/underscore/hyphen), no error/incomplete result, and one completed assistant message containing one output_text part. Refusals and tool/action output are rejected. Bounded unknown envelope fields are inert data. No generated field grants execution authority: generated steps always have Action null, including inputs that originated in mapped synthetic fixtures.

A cooperative 90-second deadline covers the key callback, HTTP and body reads. Await actual callbacks/transport/streams even if they ignore cancellation; do not abandon work with WaitAsync or Task.Run. Successful bodies require unencoded application/json with optional UTF-8 charset, at most 256 KiB plus one overflow byte, strict UTF-8, depth at most 32 and no duplicate properties anywhere. Refuse a response containing the supplied credential before constructing a capture. Safe errors have a closed enum, fixed messages and no upstream exception/body. 401/403, 429, other HTTP/network, incomplete/refused, malformed/oversized, unavailable-key and elapsed deadline remain distinguishable at the pure-client boundary. Only one integer Retry-After in 0–86400 seconds is retained for 429. Caller cancellation is sanitized after actual work settles.

`AiGenerationCapture` defensively exposes the exact input bytes and SHA-256, raw response bytes, model, response ID, ordered original traces and generated plain case/step values. No credential field exists. The capture is immutable under caller mutation.

## Publication and provenance

Add `TestingController(context, adapter, figmaReader, aiGenerator)` while preserving the existing two- and three-argument constructors. Add `GenerateWithAiAsync(sourceIds, getKey, cancellationToken)`. Admission precedes caller enumeration. The controller captures 1–8 distinct source IDs, flushes the current draft before external work, reads snapshots through its captured project facade, and links caller cancellation with project lifetime. Existing serialized authoring, actual-work retention, before-leave and Stop barriers apply.

Publish a receipt source first, kind Requirements, provider `openai.responses.test-cases`, provider version `1`, document ID equal to response ID. Its OriginalBytes is bounded UTF-8 JSON containing schema version 1, requested/observed model, response ID, exact input UTF-8 in `inputUtf8Base64`, `inputSha256`, exact response UTF-8 in `responseUtf8Base64`, `responseSha256`, and original trace identities. Base64 preserves byte identity, whitespace and escape spelling; a parsed JSON reserialization is not equivalent. Receipt items have stable `case-1` etc. locators, the generated title, a clear AI/manual-review description, one criterion per generated step equal to that step's expected result, and VirtualScenario null. The original/source and Core envelope caps are unchanged.

Build a new case set named `AI 测试用例（待人工审核）`. Every case has the exact original criterion trace and its receipt item criterion 0; every step has the original trace and its own receipt criterion index. Prefix prerequisites with `AI generated; manual review required. Model: gpt-5.4-mini-2026-03-17.` and retain model prerequisites, refusing overflow rather than truncating. All actions are null. CSV keeps both original and receipt traces.

Each publication uses the same controller-lock admission ticket as Figma; the actual facade call is outside the lock. Update acknowledged summaries directly, with no fallible list refresh or cancellation relabel after acknowledgment. These are two independent store calls, not a transaction. Return `AiGenerationPublication(Receipt, CaseSet, State, ErrorCode)` with State Created, Cancelled, Closed or Failed. Before receipt acknowledgment, errors/cancellation throw normally. Once receipt acknowledgment exists, a failure/cancellation/closure before case-set acknowledgment returns a partial publication with CaseSet null, the acknowledged receipt and a closed safe error code; never auto-retry or delete it. A case-set acknowledgment yields Created even if cancellation/Stop arrives immediately afterward. Failed uncertain commits remain on disk for explicit refresh; no success is inferred without acknowledgment. Select an acknowledged new set only after flushing the prior draft succeeds.

## Native workflow

The production testing entry registers secret metadata `figma-token` / `Figma 访问令牌` and `openai-api-key` / `OpenAI API 密钥` during InitializeAsync. Values use only captured project `IPluginSecretStore.ReadAsync`; no environment, .env, settings, logs, fixtures or command metadata contain credentials. The host's existing native credential UI and Windows protection remain authoritative; unsupported storage does not enable a remote operation.

Add a native source panel to the existing testing page. Figma fields are file key, optional version, and 1–16 node rows, each with node ID and one acceptance criterion per line. Start with one row; adding/removing rows preserves other text. Keep an in-memory project-session draft in the plugin so page unload/reopen preserves current inputs, including after errors. Explain that successful imports are durable while the unsubmitted form is session-local. Capture all actual control values synchronously in the owned click prefix. Do not add a save checkbox/button.

An explicit `读取 Figma 并导入` action performs one import with its captured secret callback. An explicit `发送所选来源到 OpenAI 并生成` action requires at least one selected source and never silently falls back to all sources. Before that button, show the model and explain that selected titles/descriptions/criteria and source identities/versions are sent to OpenAI, may incur charges and require human review; they will not start automation. Do not send data during initialization, form changes, navigation, normal generation, restart or refresh. Keep existing local imports and deterministic generation intact.

A `取消远程操作` action requests cancellation of the current remote operation; ownership and the busy state remain until actual work settles. Stop and project leave retain that actual task, including credential callbacks and UI continuations. Failure preserves form and selected dirty draft. Show fixed readable errors without raw provider data. Show partial receipt publication explicitly and do not replace it with an unconditional success message. Update existing page/manifest/delivery copy so it no longer claims the plugin never accesses remote services; virtual execution and frames remain explicitly SIMULATED.
