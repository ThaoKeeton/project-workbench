# 导出错误报告

如果工作台显示“项目尚未就绪”或“工作台未能启动”，点击“导出错误报告…”，选择一个可写的本地文件夹。应用会保存 `Workbench-error-<随机编号>.json`。你可以自行检查这个 JSON 文件，再将它发给支持人员分析；应用不会自动上传或发送报告。

报告在内存中生成，不需要读取配置、凭据或项目文件。因此，原数据目录被占用或无法访问时，仍可尝试导出到其他可写文件夹。导出只会创建新文件，不会替换已有报告、删除锁文件或修改项目数据。取消选择文件夹不会写入报告；同名文件已存在时会保留原文件，请使用已有报告或改选文件夹。

## 默认包含

- 随机报告编号和 UTC 时间。
- 应用版本及可验证的应用构建提交号，不是用户项目的提交号。
- .NET 运行时版本、系统版本号和进程架构。
- 固定的失败阶段、错误码、分类，以及可取得的数字系统错误码。

默认不包含文件路径、Windows 用户名、机器名、项目名称或编号、配置、密钥、正文、环境变量、日志、异常原文、堆栈或内部异常。未知异常只会记录安全的通用分类；不能仅凭通用分类认定具体根因。

## 常见提示

- `UserStoreInUse`：另一个实例占用数据目录。先正常退出该实例，再重试；不要手工删除锁文件。
- `StoreAccessDenied`：当前账户不能访问数据目录。检查读写权限，或先向其他目录导出报告。
- `StoreDirectoryUnavailable`：磁盘或目录暂不可访问。
- `ApplicationFileMissing`、`ApplicationFileInvalid`、`ApplicationFileLoadFailed`、`NativeDependencyMissing`：应用文件或依赖无法载入。保留数据目录，退出后完整解压同一版本应用，再检查。
- `InvalidCatalog`、`RecoveryRequired`：保留项目列表与目录，先导出报告，再决定是否使用界面提供的恢复操作。

报告保留当前操作最早捕获的失败，之后的回滚或等待不会改写这份快照。真正重新尝试初始化后，新的失败会生成新的报告编号。

## 范围

此入口覆盖应用已经能够显示窗口后发生的宿主或项目初始化失败。若 WinUI、原生依赖或应用入口在窗口显示前就失败，无法使用这个应用内入口。报告是定位证据，不代表问题已经修复。
